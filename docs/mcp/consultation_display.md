## 1. 화면에서 바뀐 내용

### 1.1 공통 메시지 컴포넌트

새 답변, 확인 질문·자가조치 응답, 저장된 상담 이력은 같은 [ConsultationMessage.jsx][consultation-message]를 사용합니다.

| 영역 | 담당 내용 |
| --- | --- |
| 대화 본문 | 안내 요약 |
| 도구 카드 | 현재 질문, 승인 단계, 비용, 보증, 공식 서비스 결과 |
| 근거 영역 | 제조사 설명, 적용 조건, 주의사항, 공식 출처 |

### 1.2 근거 합치기

[KnowledgeSources.jsx][knowledge-sources]는 아래 세 출처를 문서 ID로 합칩니다.

- 자가검진의 `references`
- 검색의 `documents/safety_notices`
- 저장된 `sources`

표시 규칙

- 같은 문서는 한 번만 표시
- 절차 보완은 원래 자료와 별도로 유지
- 안전 주의 근거는 펼친 상태로 질문·자가조치 카드보다 앞에 표시
- ID는 중복 판정에만 사용하고 화면 제목에 넣지 않음

### 1.3 고객에게 보여 주는 필드

| 영역 | 고객에게 보여 주는 내용 |
| --- | --- |
| 설명 | 제목, 증상·표시 의미, 원문에 기재된 원인·상황 |
| 조건 | 선행 조건, 실제 그림·부품·기능·현재 상태 확인 조건, 분기별 적용 조건 |
| 모델 | 자료에 기재된 모델, 조건부 모델, 제외 모델(실행 승인과 구분) |
| 출처 | HTTPS 출처와 원문 절·페이지, 링크가 없으면 없다고 표시 |
| 자가검진 | 현재 승인 단계와 결과 버튼, 조건 질문, 해결·미해결·조건 미충족·미승인 사유 |
| 비용 | 서버 금액·범위·중앙값·신뢰도·사례 수·방문 가산·고지, 미확인은 추가 확인 필요 |
| 보증 | 저장된 전체·주요 부품 보증, 부품비·기술료·출장비의 조건부 무상 또는 확인 필요 |
| 서비스 | 지역 기준과 센터, 공식 접수 링크, 복사 가능한 전송 전 상담 요약 |

### 1.4 표시하지 않는 것

- 실행되지 않은 부품 가격 문의를 고장 진단으로 표시하지 않음
- 후기·후보별 비용은 합산하지 않음
- 정보가 빠진 저장 결과는 미확인으로 표시하고, `0원`이나 예약·외부 전송 완료로 바꾸지 않음
- 보증 결과가 별도 `warranty`와 도구 `check_warranty.data`에 함께 있으면 저장된 별도 결과를 한 번만 표시

## 2. 저장된 과거 JSON 처리

### 2.1 읽는 필드

[customerDisplay.js][customer-display]는 표시 시점에 과거 B30 `content/text`의 JSON 래퍼를 읽습니다.

- 사용하는 필드
    - `record`와 `record.content`의 명시된 설명 필드
    - 원래 조건·주의사항과 현재 QA의 조건·주의사항
    - 유효 모델 목록, 공식 출처
- 내부 QA 판정 이력이나 전체 객체는 평탄화하지 않음

### 2.2 실행 단계와의 구분

- 과거 원문 조치·순서·분기별 `action_summary`를 실행 단계로 복원하지 않음
- 실제 실행 단계와 버튼의 출처: 서버 `get_diagnostic_plan.data.steps/question`
- 과거 자료에는 저장 당시 설명이며 현재 승인·최신 정책이 아니라는 문구 표시
- 일반 텍스트 근거도 그대로 읽음

### 2.3 JSON·내부 정보 처리

- 대화 본문에 포함된 JSON이나 잘린 JSON: 상세 근거 확인 안내로 표시
- 알 수 없는 JSON 구조: 그대로 출력하거나 의미를 추측하지 않음
- 고객 표시에서 제외: 코드 파일 경로, 해시, 내부 키
- 기능 범위 밖: 임의의 과거 응답 문장 재생성, 모든 과거 자료의 현재 사실 검증

### 2.4 원본 보존과 DEV 영역

- 변경하지 않는 것: DB·API 응답·React의 원본 메시지
- 하지 않는 것: 이력 마이그레이션, 원문 덮어쓰기, 재조회 시 보증 재계산
- DEV 영역: 기존 `import.meta.env.DEV`의 [ToolCallTrace.jsx][tool-call-trace]에 원본 tools와 원본 답변·검색 근거를 별도 접힌 영역으로 제공
- 운영 빌드에는 DEV 패널 문구와 호출 이력 조회 경로가 포함되지 않음

### 2.5 유지한 화면

- 마이페이지, 제품 등록/수정, 전체 화면 디자인 유지
- 별도 제품 선택·보증 입력 폼은 추가하지 않음
- CSS 변경 범위: 공식 경로 줄바꿈, 근거 분기 구분, 긴 근거 문장의 줄바꿈

## 3. 검증과 재현

### 3.1 실행 명령

저장소 루트에서 Node 24로 실행합니다.

```powershell
Set-Location .\frontend
npm test
npm run lint
npm run build
npm run test:display:browser
```

### 3.2 브라우저 검사 환경

- 기본 브라우저: Windows에 설치된 Edge
- 다른 실행 파일 지정: `$env:BROWSER_EXECUTABLE='브라우저 실행 파일의 절대 경로'`
- 격리: 새 로컬 포트와 임시 프로필 사용, 기존 브라우저·사용자 계정·서비스에 접속하지 않음
- HTTPS 외부 요청 차단
- 화면 캡처와 임시 프로필은 시스템 임시 폴더에 남고, 실행 서버와 테스트 브라우저는 종료

### 3.3 검증 결과

- 프론트엔드 22개 통과: 기존 스트림 10개, 표시 투영 6개, 실제 React 컴포넌트 렌더링 6개
- 실제 원본 1,542건·구조화 1,542건의 표시 결과에 내부 메타데이터·실행 단계가 섞이지 않는지 검사
    - 대표 진동 3분기·선택 기능 조건, OE 설명·출처, 적용 제외 모델 확인
- 저장 JSON·일반 텍스트·잘린/알 수 없는 JSON·누락 필드 처리, 원본 입력 불변, 자가검진/검색/저장 근거의 중복 제거와 안전 우선 표시 검사
- 현재 조건/단계 버튼과 과거 이력의 비활성 상태, 비용의 정확한 값·미확인 표시, 조건부 보증·부분 조회·전송 전 요약 검사
- 실제 Edge의 로컬 화면 데이터로 확인한 항목
    - 조건 응답·단계 응답의 ID/범위/버전 전달 값
    - 증상·위험 응답, 복사 성공·실패
    - 390px/1280px에서 가로 넘침 없음과 화면 캡처
- lint·운영 build 통과, 빌드 자산에 DEV 패널·원본 영역 문구와 `/tool-calls` 경로 없음 확인

### 3.4 검증 범위

- 변경하지 않은 것: 백엔드, Python, MCP 입력/출력 계약, 제조사 데이터
- 이 검증의 범위: 화면과 로컬 데이터 형식의 검사
- 범위 밖: 실제 OpenAI 상담 품질, 실물 수리, 운영 사용자 DB의 모든 과거 응답, 전체 사용자 이해도 평가
- 참고: 실제 API·DB·MCP 연결의 6단계 결과는 [6단계 기록](repair_followup.md), 전체 실제 상담 평가는 [8단계 기록](consultation_validation.md)
