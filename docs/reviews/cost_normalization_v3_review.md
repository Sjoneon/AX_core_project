## 2. 무엇을 계산하는 패키지인가

이 패키지는 학습된 대형 언어 모델이나 MCP 서버가 아니라 **기준값·해외 부품가·국내 사례를 사용한 오프라인 통계 계산 코드**다. OpenAI 호출, 제품 소유권, 상담 상태, 보증 판정, 공식 예약은 포함하지 않는다.

| 단계 | 실제 계산 | 결과의 의미 |
|---|---|---|
| normalize | 해외 세전 금액 × 고정 환율 × 한국 VAT 1.10 | 한국 기준 해외 가격 참고값 |
| normalize | (국내 과거 총액 − 당시 출장비) × CPI 비율 + 기준 출장비 | 국내 사례의 기준 시점 보정 총액 |
| v1 | 해외 부품가에 국내/해외 관측 비율 적용, 제품군 기술료 더함 | 구성별 부품비·기술료·출장비 추정 |
| v2 | 기술료를 T1 전장·센서 / T2 기계부품 / T3 대분해·냉매 등급으로 변경 | 작업 난이도를 반영한 구성 합계 |
| v3 | v2 합계와 같은 부품 그룹 국내 실제 총액 중앙을 로그 공간에서 결합 | 구성 합계와 별도인 경험적 참고 총액 |

v3의 결합은 단순 산술 평균이 아니다.

```text
n = 비교 가능한 국내 같은 부품 그룹의 사례 수
w = n / (n + 2)
v3 중앙 = exp(w × ln(국내 총액 중앙) + (1-w) × ln(v2 총액))
n = 0이면 v3 중앙 = v2 총액
v3 범위 = [중앙 / exp(q), 중앙 × exp(q)]
기존 로그의 exp(q) ≈ 1.359
```

코드의 기준일은 2026-10-08이며 환율은 USD 1,340.00, EUR 1,501.07, GBP 1,770.94, INR 13.85를 고정한다. CPI 기준 120.43과 평일 출장비 28,000원 등도 고정 입력이다. 이번에 그 환율·물가·출장비의 원출처를 재검증하지 않았으므로 현재 공식 값으로 표시하지 않는다.

v1의 국내/해외 부품가 비율 중앙은 기존 로그에서 미국 0.308, 유럽 0.95다. 개별 부품번호의 국내 관측 8건으로 만든 그룹 보정이며 한국 공식 수리 부품 공급가 목록을 의미하지 않는다. v2 기술료 중앙은 T1 26,412원(12건), T2 35,608원(9건), T3 106,823원(3건)이다. 난이도별 국내 기술료에는 LG·삼성 사례가 함께 들어간다.

`overseas_v1.csv`를 읽은 결과는 총 87행이다. 부품비 71행, 기술료 9행, 총액 5행, 출장·진단비 2행으로 나뉜다. 부품비 71행 중 숫자 세전 금액이 있는 행은 67행이며, 그 행들의 서로 다른 부품번호는 63개다. 가격 비공개·확인 실패 등을 기록한 4행은 가격 관측으로 집계하지 않는다.

위 링크는 각 가격을 확인한 공식 페이지다. 확인일은 2026-10-13이며, 회원·쿠폰·배송 조건에 따라 실제 주문 금액은 달라질 수 있다. 소모품 표시 가격을 기술료·출장비가 포함된 수리 청구액으로 사용하지 않는다. 가격이 있다는 사실만으로 사용자의 기기에 호환되거나 교체가 필요하다는 뜻도 아니다.

현재 로컬 `knowledge.json`에는 호환 기록 9행·고유 부품번호 8개가 있다. 김치냉장고 관련 4756JA3001H와 MCS62101823의 원본 기록 2행은 현재 검색 파일에 빠져 있다. ADQ75373205는 원본에서 여러 적용 모델의 별도 기록이 있으므로 위 표의 단일 부품번호가 모든 리비전의 승인을 뜻하지 않는다.

### 4.1 해외 원자료와 B30 부품번호를 대조한 결과

B30의 고유 부품번호 10개 중 해외 CSV에서 같은 번호가 발견된 것은 `383EER2001A` 하나다. 독일/영국의 2행에 가격이 있으나 그룹 코드는 `-`, 허용목록은 '목록 외'다. 나머지 9개 번호는 해외 CSV의 정확 부품번호 값과 일치하지 않았다.

| 원자료 번호 | 부품번호 | 국가 | 당시 표시 가격 | 세전 금액 | 그룹 | 확인일 |
|---|---|---|---|---|---|---|
| 57 | 383EER2001A | 독일 | EUR 13.82 | EUR 11.61 | 목록 외 | 2026-10-08 |
| 74 | 383EER2001A | 영국 | GBP 11.99 | GBP 9.99 | 목록 외 | 2026-10-08 |

근거는 [해외 원자료](https://drive.google.com/file/d/1cjzuQI_NMQzg05lfdh9XaDsTY48hGy6M/view)의 해당 행이다. 독일 행은 공인 파트너 판매처, 영국 행은 비공식 판매처로 기록돼 있으며 세금 처리 조건도 다르다. 이번 확인에서 해외 판매처의 가격을 재조회하지 않았다.

따라서 B30 호환 부품번호 10개와 수리비 그룹 33개를 같은 부품 목록으로 합칠 수 없다. 예를 들어 배수 펌프 거름망 383EER2001A를 W01 배수펌프 전체 교체 가격에 연결하면 대상 부품이 달라진다.

## 5. 실행 입력·출력과 누락 파일

README의 순서는 normalize → model → model_v2 → model_v3다. 실제 코드의 파일명은 README의 한국어 결과 이름과 다르다.

| 단계 | 실제 입력/의존 | 코드의 출력 |
|---|---|---|
| normalize | `overseas_v1.csv`, 국내 LG 후기 CSV, 국내 삼성 후기 CSV | `out_overseas_normalized.csv`, `out_domestic_normalized.csv` |
| model | 위 정규화 2개 CSV, 코드 내부 KR_PART 관측값 | `out_estimate_table.csv`, `out_validation.csv` |
| model_v2 | model의 자료·함수, `out_validation.csv` | 비교 표를 콘솔에 출력; 별도 CSV 저장 없음 |
| model_v3 | model/model_v2와 `out_validation.csv` | `out_validation_v3.csv`, `out_model_compare.csv`, `out_estimate_table_v3.csv` |

검토 당시 코드는 작성 당시 실행 환경의 절대 경로로 중간 CSV 폴더(`norm/`)와 `LG_AS_수리비_후기_사례.csv`, `삼성_AS_수리비_후기_사례.csv`를 직접 읽었다. 이후 경로는 환경변수 `COST_DATA_DIR`(지정하지 않으면 스크립트가 있는 폴더) 기준으로 바꿨고 계산 로직은 바꾸지 않았다. 국내 후기 원본과 정규화/검증 중간 CSV는 현재 확인한 패키지 폴더에 없다. 관련 Drive 검색에서도 원본을 확보하지 못했지만, 사용자의 다른 저장소까지 없다고 단정할 수는 없다.

필요 라이브러리는 pandas·numpy이며 패키지의 별도 의존성 고정 파일은 폴더 목록에서 확인되지 않았다. model을 import하면 CSV를 바로 읽기 때문에 현재 서버에서 `predict3`만 가져와 즉시 사용하는 방식도 입력 경로가 없으면 실패한다.

지금 가능한 일은 이미 생성된 최종 표·로그·코드를 읽어 구조를 이해하고 고정 스냅샷을 활용하는 것이다. 원자료부터 재계산하려면 국내 원본 확보, 경로 설정화, 라이브러리 버전 고정, 실제 출력과 배포 파일명의 대응이 필요하다.

## 6. 기존 평가 결과와 검수 항목

| 지표 | v1 | v2 로그 | v3 |
|---|---:|---:|---:|
| ±5% 이내 | 2/20 | 4/20 | 6/20 |
| ±10% 이내 | 5/20 | 7/20 | 10/20 |
| ±20% 이내 | 12/20 | 12/20 | 11/20 |
| 중앙 절대오차 | 17.0% | 17.5% | 11.2% |
| 평균 절대오차 | 22.0% | 20.7% | 17.2% |
| 범위 적중 | 65% | 70% | 80% |

이는 패키지의 기존 실행 로그와 비교 CSV에 기록된 LG 유상 20건 평가다. 이번에 재실행한 성능이 아니다. 등급·축소 강도·범위 폭을 같은 표본에서 정한 한계가 있고 ±20% 적중은 v3에서 줄었다. '80% 범위'를 독립적인 실사용 보장 확률로 표현하지 않는다.

코드와 로그에서 후속 검수가 필요한 부분도 확인했다.

- `normalize_domestic`은 '견적만'을 표시하지만 유상 실결제 판단에서 그 플래그를 직접 제외하지 않는다. 원본을 확보한 뒤 견적만인 사례의 학습 유입을 확인해야 한다.
- 부품비가 100원 미만이면 결측으로 바꾸고 일부 계산에 truthiness를 사용하므로 확인된 0원과 미기재가 섞일 수 있다. 무상 처리 전 정가와 실제 지불액을 따로 보존해야 한다.
- 과거 출장비 미기재 사례를 추정값으로 보정하며, 여러 부품을 바꾼 후기도 단일 그룹으로 매핑될 수 있다. 당시 요금 가정·복합 수리 여부를 명시해야 한다.
- v3 보정 POOL은 고객과실 등을 제외하지만 기존 검증 목록에는 고객과실 W11 사례가 남아 있다. 학습 모집단과 평가 모집단의 조건을 분리해서 검토해야 한다.
- 최종 표에는 구성별 범위가 없지만 v1/v2 코드·로그에는 추정 범위가 있다. 입력·산출물을 확보해 검증하기 전 로그 범위를 현재 앱에 그대로 채우지 않는다.
- REFERENCE/독립 VALIDATION 분리와 중복 후기 제거가 필요하다. 기존 LOO 기록만으로 독립 검증이 완료된 것으로 평가하지 않는다.

## 7. 현재 프로젝트와 연결된 상태

현재 [parts.json](../../backend/src/main/resources/homecare/parts.json)은 D02를 제외한 32개 그룹의 `partMedian`, `laborMedian`, `baseVisit`, `empiricalMedian/Min/Max`, 사례 수·등급·기준일을 보관한다. [ToolDataCatalog.java](../../backend/src/main/java/com/project/backend/mcp/tool/ToolDataCatalog.java)가 이를 읽고 Spring의 [EstimateRepairCostTool.java](../../backend/src/main/java/com/project/backend/mcp/tool/handler/EstimateRepairCostTool.java)가 비용 결과를 반환한다.

현재 숫자의 구분은 다음과 같다.

| 정보 | 존재 여부 | 현재 앱 연결 |
|---|---|---|
| B30 실물 부품번호·선택 SKU 호환 | 원본 11행/10번호 있음 | 일부 9행/8번호, 실행/구매 확정 아님 |
| 국내 공식몰 소모품 가격 | 위 10페이지에서 표시 확인 | 가격 필드로 저장·도구 연결되지 않음 |
| 해외 실물 부품번호별 과거 가격 | 숫자 가격 67행/63번호 있음 | 그룹 추정의 원자료, 국내 모델 호환 미확인 |
| 한국 기준 부품 그룹 추정값 | 원표 33개 있음 | 32개 연결 |
| 증상·오류→부품 그룹 매핑 | 운영 자료 없음 | 현재 `targetCodes` 0/32개 |
| 사용자 모델/SKU→수리용 부품→공식 국내 수리 공급가 | 완성된 연결 없음 | 확정 부품 견적 제공 불가 |
| 새 국내 후기 원본·독립 평가셋 | 이번에 확보하지 못함 | 재계산/새 평가 보류 |

제품 원문과 비용 데이터를 연결할 때는 '증상/오류→검토된 원인 그룹→정확 부품/SKU→가격 출처'를 별도 계약으로 만든다. 공식 소모품 구매 참고가와 추정 수리 총액을 별도 카드로 유지하고, 국내 호환·가격이 없는 항목은 확인 필요로 둔다.

관련 검수는 [제품 데이터 활용성 보고서](product_data_usability_review.md), 전체 개발 흐름은 [개발 가이드](../guides/repair_development_guide.md)를 참고한다. 이번 확인 결과를 앱·원자료의 가격 갱신 또는 모델 재학습 완료로 해석하지 않는다.
