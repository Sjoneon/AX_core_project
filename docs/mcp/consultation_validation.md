# 실제 상담 평가와 회귀 검증 — 8단계

작성일: 2026-10-15 (Asia/Seoul). 기준 커밋 `e3394c5` 이후 작업본, 데이터 `B30-COST-V3-20261014-R5`.

## 무엇을 통과로 보는가

분류명이나 도구 호출의 `OK`만으로 상담 성공을 판정하지 않는다. [사전 시나리오](consultation_evaluation.json)는 기대 근거·제외 문서·질문·도구·금액·상태를 고정한다. 사용자 요청에 따라 [답변 적합성 기준](consultation_answer_rubric.json)을 별도로 정해 실제 질문과 최종 문장을 대조한다.

답변에서는 질문에 직접 답했는지, 현재 제품·증상에 맞는 설명인지, 근거와 일치하는지, 필요한 다음 행동이 구체적인지, 무관한 설명이 핵심을 가리는지 확인한다. 정보가 부족하면 무엇이 부족하며 어떻게 확인할지 설명해야 한다. 침수 뒤 재가동 문의에 일반 증상 선택만 제시하거나, 접수 문의에 ‘준비했습니다’만 답하면 실패다.

자료 부족을 설명하고 공식 점검을 안내한 답변은 적합할 수 있지만 수리 완료가 아니다. 해결도 테스트 사용자의 해결 보고이며 실물 검증과 구분한다. 비용은 부품 그룹 문의의 참고값이고 실제 고장 부품을 맞힌 결과가 아니다.

## 실행 환경과 기록

[ConsultationEvaluationTests.java](../../backend/src/test/java/com/project/backend/mcp/ConsultationEvaluationTests.java)는 별도 `real-agent` 태그로 실행한다. 일반 `test/mysqlTest`에서는 제외한다. 실제 설정 모델·임베딩, 별도 포트의 Spring HTTP/JWT·FastMCP, 격리 H2와 합성 계정·제품을 사용한다. 개발/운영 사용자 DB·기존 실행 프로세스·키는 변경하지 않는다. 조건/단계 버튼과 이력 저장도 실제 API로 확인한다.

먼저 모델 연결을 확인하고 기존 제조사 임베딩 캐시를 사용한다. 캐시가 없으면 정상 생성 비용이 발생한다. 보고서에 모델·자료 버전·기준 커밋·작업본 여부·시나리오 해시·실행 클래스 해시, 질문/답변·상태·도구 결과·호출 주체·시간을 남긴다. 키·JWT·계정 이메일은 남기지 않는다. 기존 보고서는 덮어쓰지 않는다.

`MODEL`은 모델 선택, `POLICY_FALLBACK`은 서버 보완/정책, `SAFETY_POLICY`는 안전 정책이다. 비용·서비스·승인 단계는 정책 경로가 많으므로 이를 모델의 도구 선택 성공률로 계산하지 않는다. 전체 지연에는 짧은 버튼 응답도 포함되므로 일반 채팅과 버튼의 시간을 구분해 해석한다.

첫 실행 `initial`은 평가기에 잘못 넣은 API 기본 경로로 모델 호출이 실패했다. 원본 보고서를 보존하지만 실제 모델 품질의 기준선에서 제외한다. 경로를 제거하고 SDK 기본값과 연결 확인을 사용한 `baseline`부터 비교한다.

## 결과 읽는 방법

실제 실행별 JSON은 `docs/benchmarks/consultation_agent_20261015_*.json`에 보존한다. `baseline`은 개발 질문 24개 중 상태/근거 검사를 22개 통과했다. 첫 수정 실행 `final`은 24개를 통과했지만 답변 검토에서 무관한 비용 부속 설명과 부정 문장의 재질문이 남아 추가 수정했다. 이후 `final_v2`는 23개로, 모델 오류가 난 다른 모델 진동 문의에 불필요한 증상 재질문을 확인했다. 단일 실행의 통과 수를 상담 품질 확정으로 사용하지 않은 이유다.

[추가 표현 세트](consultation_holdout.json)는 개발 문구와 다른 표현, 냉장고 침수/냉각·식기세척기 전원 문의를 실행 전에 정했다. 최초 실행의 인용 문구 오탐도 보존한다. 수정 후 최종 실행과 실제 답변 검토의 결론은 평가 보고서와 함께 구분해 기록한다.

보조 평가기 [evaluate_consultation_answers.py](../../backend/scripts/evaluate_consultation_answers.py)는 질문·실제 답변·도구 근거를 같은 계열 모델로 검토한다. 원문에 없는 인용은 미검토로 남긴다. 미승인 조치의 거절을 감점하거나 일반적인 평가 문구만 내는 오판이 있어 이 점수를 고객 답변의 최종 통과율로 사용하지 않는다. 원본 비평과 실패/미검토도 보존하고 실제 문장·근거 대조가 필요하다. 독립된 사람의 평가가 아니다.

## 재현

일반 회귀 검사는 [검증 가이드](../guides/verification_guide.md)의 명령을 사용한다. 유료 실제 상담 평가는 저장소 루트에서 다음과 같이 실행한다.

```powershell
$env:HOMECARE_TEST_PYTHON=(Resolve-Path '.\mcp_server\.venv\Scripts\python.exe').Path
$env:JAVA_HOME='C:\Users\Roneon\.jdks\openjdk-21.0.1'
$env:PATH="$env:JAVA_HOME\bin;$env:PATH"
$env:DEBUG='false'
$env:HOMECARE_EVAL_RUN_ID='new_run_01'
Set-Location .\backend
.\gradlew.bat evaluateConsultationAgent --offline --no-daemon
```

추가 표현은 `HOMECARE_EVAL_SPEC=docs/mcp/consultation_holdout.json`과 새로운 실행 ID를 지정한다. 일부 사례만 실행하려면 `HOMECARE_EVAL_CASES`에 쉼표로 ID를 나열한다. 부분 실행을 전체 평가로 기록하지 않는다. 일반 테스트에는 기존 키가 필요하지 않다.

보조 답변 검토는 루트에서 실행하며 별도 API 비용이 발생한다.

```powershell
python -I backend/scripts/evaluate_consultation_answers.py --input docs/benchmarks/consultation_agent_20261015_baseline.json --output docs/benchmarks/consultation_answers_new_run.json
```

실물 수리, 240문장 전체 명세 평가, 사용자 과업/이해도 시험, 운영 DB·MySQL 마이그레이션·Docker/Linux 배포는 이 로컬 평가로 완료 처리하지 않는다. 일반 증상→부품 매핑, 검증 후기·지역 센터 확대, 부품보유기간·요청 멱등성·이용 이벤트 등의 자료/기능 제한도 별도다.

증상 기반 비용·제조사 확인 사항 노출은 별도 후속 제안이다. 8단계에서는 반복 보증·요약 축약과 실제 접수 정보 제공을 적용했지만, 미승인 조치를 참고라는 이름으로 실행 안내하거나 근거 없는 증상→부품 연결을 만들지는 않았다. 기존 승인·모델 조건과 사례 기준을 유지한 상태에서 확인된 답변 범위만 기록했다.
