# HomeCare AI 프론트엔드

흰색·버건디 색상, 제품 선택 카드, 상담 내역 사이드바, 하단 입력창을 적용했습니다.
회원가입·로그인 후 제품 카테고리를 선택하고 질문을 입력하면 Spring Boot 백엔드에 보내고 답변을 표시합니다.

## 로컬 실행

Node 24를 사용합니다. nvm 사용 시 `frontend` 폴더에서 `nvm use`를 실행하면
`.nvmrc`에 지정한 버전을 선택합니다.

프로젝트 루트에서 터미널 두 개를 사용합니다.

첫 번째 터미널 — 백엔드 실행:

MySQL의 `project_db`와 `backend/.env`의 `JWT_SECRET`이 필요합니다.
현재 로컬 설정에는 JWT 서명 키가 추가되어 있습니다. 자세한 설정은 `backend/README.md`를 참고하세요.

```bash
cd backend
./gradlew bootRun
```

두 번째 터미널 — 프론트엔드 실행:

```bash
cd frontend
npm ci
npm run dev
```

이미 의존성이 설치되어 있다면 `npm ci`는 생략할 수 있습니다.
브라우저에서 **http://127.0.0.1:5173**을 엽니다.

`vite.config.js`에서 `/api` 요청을 `http://127.0.0.1:8080`으로 프록시합니다.
브라우저는 프론트엔드와 같은 주소로 요청하므로 백엔드의 CORS 설정을 추가할 필요가 없습니다.
백엔드 포트를 변경했다면 프록시 주소도 변경하고 프론트엔드를 다시 실행하세요.
기존 Docker 서버와 IPv6 주소가 섞이지 않도록 명시적으로 `127.0.0.1`을 사용합니다.

API 키는 기존 `backend/.env`에서 백엔드만 읽습니다. 프론트엔드에는 키를 넣지 않습니다.

## 사용

- 처음에는 로그인 화면이 표시됩니다. 계정이 없다면 **회원가입**으로 전환해 가입한 뒤 로그인합니다.
- 로그인 성공 시 이메일과 상담 화면을 표시합니다. 잘못된 비밀번호나 중복 이메일은 오류로 안내합니다.
- 새 상담에서는 **냉장고·세탁기·건조기·식기세척기** 중 카테고리를 선택합니다. 상세 모델 선택과 사진 첨부는 없습니다.
- 증상을 입력하고 **상담 시작** 또는 **Enter**로 전송합니다. 카테고리 미선택 또는 빈 입력은 전송할 수 없습니다.
- 제품별 예시 질문을 누르면 해당 카테고리와 입력 내용을 채워줍니다. 전송 전 수정할 수 있습니다.
- **Shift + Enter**는 줄바꿈이며, 한글 조합 중의 Enter는 전송하지 않습니다.
- 최대 4,000자까지 입력할 수 있고 응답을 기다리는 동안 중복 전송을 막습니다.
- AI 답변은 생성되는 대로 표시되며 완료 후 검색 근거와 저장된 상담 내역을 갱신합니다. 위로 스크롤해 이전 내용을 읽는 동안에는 자동으로 맨 아래로 이동하지 않습니다.
- 스트리밍 API가 없는 로컬 MCP 백엔드는 404·405에 한해 기존 `/api/chat` JSON 응답을 사용합니다. 인증 실패·요청 제한·서버 오류나 중단된 스트림은 자동 재전송하지 않습니다.
- 상담 화면에는 별도의 등록 제품 선택 영역을 두지 않습니다. 선택한 품목의 등록 제품이 하나면 백엔드에서 자동 연결하고, 여러 개면 대화에서 표시 이름·정확한 모델명으로 구분합니다. 다른 모델을 입력하면 보유 제품으로 대체하지 않습니다.
- 상담은 DB에 저장된 제품 정보를 사용하며 추가 수동 등록·수정은 기존 마이페이지에서 진행합니다. 상담 화면에는 별도 보증 입력·제품 등록 양식을 두지 않습니다.
- 위험 의심 문장은 AI 문맥 판정 후 답변 안에서 확인 질문과 **예·아니요·모르겠어요** 버튼을 표시합니다. 선택한 답과 다음 질문·안내가 대화에 저장됩니다. AI 판정 실패·8초 초과에는 키워드 대체 판정을 사용하며 긴급 신호는 바로 안전 안내를 제공합니다.
- 요청 실패 시 오류를 표시하고 입력을 복원하여 다시 전송할 수 있습니다.
- 스트림이 중단되면 임시 질문·미완성 답변을 제거하고 입력을 복원합니다. 완료 확인 없이 연결이 끊겼다면 상담 내역을 확인한 뒤 재시도하세요. 화면을 떠나면 진행 중인 연결도 종료합니다.
- 답변 아래 **검색 근거 · 가상 테스트 매뉴얼**에서 문서 ID와 제목을 확인하고 항목을 펼쳐 버전·파일·본문을 볼 수 있습니다. 실제 제품 수리 지침이 아닙니다.
- 검색 근거는 답변 생성에 전달한 문서이며, 모든 항목을 답변에서 인용했다는 의미는 아닙니다. 이전 상담을 다시 열어도 당시의 근거를 확인할 수 있습니다.
- 성공한 질문과 답변은 계정별로 MySQL에 저장합니다. 첫 질문의 앞 50자를 대화 제목으로 사용합니다.
- **내 상담 내역**에서 품목·제목·갱신 시간을 확인하고, 상담을 선택해 전체 질문·답변을 조회합니다.
- 내역은 오늘·어제·이전 상담으로 구분하며, 제목과 카테고리로 검색할 수 있습니다.
- 상담 옆 휴지통 버튼을 누르면 삭제 확인 창이 열립니다. **삭제**를 선택하면 해당 상담과 질문·답변이 DB에서 삭제되며, **취소** 또는 Escape는 기록을 유지합니다.
- 현재 보고 있는 상담을 삭제하면 제품 선택 화면으로 돌아갑니다. 다른 상담을 삭제하면 현재 화면과 입력은 유지합니다.
- 선택한 대화에서 질문을 보내면 해당 대화에 추가하며, 목록은 최근 갱신된 대화가 먼저 표시됩니다.
- **새 상담 시작**은 제품 선택 화면으로 전환합니다. 저장된 기록은 유지하며, 첫 질문이 성공하면 새 상담을 저장합니다.
- 왼쪽 상단 **HomeCare AI 로고**를 클릭해도 제품 선택 초기 화면으로 돌아갑니다. 로그인과 저장된 상담 내역은 유지합니다.
- 좁은 화면에서는 상단 **상담 내역 열기** 버튼으로 내역을 열고, 닫기 버튼 또는 Escape로 닫을 수 있습니다.
- **로그아웃**은 토큰과 현재 화면의 대화를 지우고 로그인 화면으로 돌아갑니다. DB의 기록은 유지됩니다.
- 목록 조회 실패 시 **다시 불러오기**로 재시도할 수 있습니다.

### 마이페이지

상단 **마이페이지**에서 등록 제품 수와 제품 정보를 조회하고 제품을 등록·수정·삭제합니다.
품목만 필수이며 구매일·설치 주소 등은 선택 입력입니다. 구매일은 숫자 8자리로 입력합니다.
주소 검색은 Kakao 우편번호 서비스를 사용하며 검색 로딩·실패 시에도 직접 입력할 수 있습니다.
선택 정보를 비우고 수정하면 저장된 해당 정보도 지워집니다. 같은 품목을 여러 개 등록할 수 있습니다.
제품은 계정별 MySQL에 저장되어 다시 로그인해도 유지됩니다.
제품 옆 **삭제**를 누르면 확인 창이 열립니다. **삭제**를 선택하면 본인이 등록한 해당 제품의 구매 정보·설치 주소가 함께 삭제되고 목록과 제품 수가 갱신됩니다.
**취소** 또는 Escape는 제품을 유지합니다. 삭제 중에는 중복 요청과 창 닫기·화면 이동을 막으며, 실패하면 확인 창에서 다시 시도할 수 있습니다.
저장 중에는 중복 제출과 모달 닫기·화면 이동을 막습니다. 실패하면 입력값을 유지합니다.
**상담으로 돌아가기**를 누르면 이전 상담·선택 품목·작성 중인 질문이 유지됩니다.

마이페이지 하단의 **회원 탈퇴**를 누르면 삭제할 데이터와 계정 이메일을 확인하는 창이 열립니다.
확인 창에서 **회원 탈퇴**를 선택하면 본인 계정과 등록 제품, 모든 상담의 질문·답변·검색 근거가 삭제되고 로그인 화면으로 돌아갑니다.
**취소** 또는 Escape는 계정을 유지합니다. 처리 중에는 중복 요청과 창 닫기·화면 이동을 막으며, 실패하면 확인 창에서 다시 시도할 수 있습니다.
탈퇴한 계정의 기존 로그인 토큰은 더 이상 사용할 수 없습니다. 같은 이메일로 재가입해도 이전 토큰은 거부됩니다.
회원 탈퇴 기능 반영 전 발급된 토큰은 계정 ID가 없어 다시 로그인해야 합니다.

에어컨은 신규 상담과 제품 등록에서 제외됩니다. 기존 상담은 **에어컨 · 지원 종료**로 표시하며
기록과 검색 근거 조회·상담 삭제만 가능합니다. 추가 질문은 보낼 수 없습니다.

로그인 토큰은 React 상태와 같은 탭의 `sessionStorage`에 보관합니다.
새로고침하면 **로그인 확인 중…**을 표시하고 `GET /api/auth/me`로 토큰을 검증한 뒤 상담 초기 화면으로 돌아갑니다.
로그인 유효기간은 기본 1시간이며 새로고침으로 연장하지 않습니다. 이전 페이지나 작성 중인 질문은 복원하지 않습니다.
만료·변조·탈퇴한 계정의 토큰은 지우고 재로그인을 안내합니다. 로그아웃·회원 탈퇴 완료 시에도 저장된 토큰을 지웁니다.
서버 연결 실패·시간 초과·서버 오류 시에는 토큰을 유지하며 **다시 시도** 또는 **다시 로그인**을 선택할 수 있습니다.
브라우저가 저장소 접근을 차단하면 기존 메모리 로그인으로 동작합니다. 탭을 닫거나 토큰이 만료되면 다시 로그인해야 합니다.
같은 계정으로 로그인하면 DB에 저장한 이전 대화를 다시 조회할 수 있습니다.
선택한 카테고리는 DB에 저장하고 후속 질문에서도 AI에 전달합니다. 상담 시작 후 품목은 변경하지 않습니다.
카테고리 기능 추가 전의 기록은 **일반 상담**으로 표시하고 그대로 이어서 질문할 수 있습니다.
기능 추가 전에 화면에만 표시된 대화는 복원할 수 없습니다.
`sessionStorage`의 `homecare.accessToken`에는 토큰만 저장하며 비밀번호와 회원 정보는 저장하지 않습니다.
`localStorage`와 쿠키는 사용하지 않습니다. 토큰을 JavaScript에서 읽을 수 있으므로 XSS에 대한 노출 위험은 남습니다.
채팅은 `POST /api/chat/stream`의 SSE를 `fetch`로 읽습니다. 채팅·대화 조회 요청에는 `Authorization: Bearer <accessToken>`을 전달하며,
인증 오류(401)가 반환되면 로그인 화면으로 돌아갑니다.
백엔드는 같은 상담의 최근 10회 문답(최대 20개 메시지, 본문 합계 24,000자)을 활용해 후속 질문에 답합니다.
문자 수 한도를 넘으면 오래된 문답부터 쌍으로 제외하며, 최신 문답만으로 한도를 넘으면 이전 기록 없이 처리합니다.
DB 원본 기록은 유지됩니다. 상담을 다시 열거나 재로그인·서버 재시작 후에도 저장된 문답에서 맥락을 복원합니다.
매뉴얼 검색에도 기억 범위 안의 최근 사용자 질문 최대 3개를 활용하므로 "그 오류는 어떻게 해결해?"처럼 이어서 질문할 수 있습니다.
다른 상담의 기록이나 오래된 문답의 요약은 활용하지 않습니다. 기억 범위 밖의 내용은 다시 알려줘야 하며 복잡한 지시어·주제 전환 해석에는 한계가 있습니다.
추가 답변 생성 호출은 없지만 이전 문답을 전달하므로 입력 토큰 사용량이 증가합니다.
AI 답변은 일반 텍스트로 표시합니다.
가상 수리 매뉴얼을 검색하는 RAG를 사용합니다. 자료에 없는 오류 코드·비용·보증 정책은 정보 부족으로 안내하도록 구성했습니다.
첫 검색에는 문서 임베딩 시간이 추가됩니다. 답변은 조각별로 표시하고 전체 채팅 요청은 최대 120초까지 기다립니다.
기존 기록은 근거 없이도 조회할 수 있습니다. 카테고리가 없는 기존 상담에서는 제품 확인을 요청하므로 제품을 선택해 새 상담을 시작하세요.
참고 프로젝트의 로컬 기록 저장이나 제안 API 대신 기존 `/api/chat`, `/api/conversations`와 계정별 MySQL 저장을 사용합니다.

## 빌드

```bash
npm run build
npm run lint
```

결과는 `dist/`에 생성됩니다. API 프록시는 Vite 개발 서버에만 적용됩니다.

### 운영 API 주소

Vercel에서는 Node 버전을 24로 선택하고, 빌드 환경변수에
현재 기존 Vercel 프로젝트 `homecare`의 Production Config에
`VITE_API_BASE_URL=https://43.202.80.116`을 등록하고 CLI로 배포했습니다.
운영 주소는 `https://homecare-omega-eight.vercel.app`입니다.
주소에는 `/api` 경로를 붙이지 않습니다. 끝의 `/`는 자동으로 제거합니다.
회원가입·로그인·상담·내역 조회·삭제·제품 조회·등록·수정 요청이 모두 이 주소를 사용합니다.

로컬에서는 이 값을 비워 두면 기존 `/api` 상대 경로와 Vite 프록시를 사용합니다.
`.env.example`을 참고해 `.env.local`에 설정할 수 있습니다.
Vite 환경변수는 빌드 시 포함되므로 API 주소를 바꾸면 다시 빌드해야 합니다.
`VITE_*` 값은 브라우저에 공개되므로 API 키·DB 비밀번호·JWT 서명 키를 넣지 않습니다.

Nginx는 위 운영 origin만 CORS에 허용합니다. Vercel은 `gwonu1/core_project`의 `main`에
연결했으며 Root Directory는 `frontend`입니다. 동일 커밋의 GitHub `ci`·`deploy`가
성공해야 운영 도메인으로 승격합니다. CLI는 저장소 루트에서 실행합니다.
[운영·자동 배포 안내](../ops/OPERATIONS.md)를 참고합니다.

설정 참고: [Vite 개발 서버 프록시](https://vite.dev/config/server-options.html#server-proxy).
