## 2. 무엇을 계산하는 패키지인가

### 2.1 패키지의 성격

- **기준값·해외 부품가·국내 사례를 사용한 오프라인 통계 계산 코드**
- 학습된 대형 언어 모델이나 MCP 서버가 아님
- 포함하지 않는 것: OpenAI 호출, 제품 소유권, 상담 상태, 보증 판정, 공식 예약

### 2.2 단계별 계산

| 단계 | 실제 계산 | 결과의 의미 |
| --- | --- | --- |
| normalize | 해외 세전 금액 × 고정 환율 × 한국 VAT 1.10 | 한국 기준 해외 가격 참고값 |
| normalize | (국내 과거 총액 − 당시 출장비) × CPI 비율 + 기준 출장비 | 국내 사례의 기준 시점 보정 총액 |
| v1 | 해외 부품가에 국내/해외 관측 비율 적용, 제품군 기술료 더함 | 구성별 부품비·기술료·출장비 추정 |
| v2 | 기술료를 T1 전장·센서 / T2 기계부품 / T3 대분해·냉매 등급으로 변경 | 작업 난이도를 반영한 구성 합계 |
| v3 | v2 합계와 같은 부품 그룹 국내 실제 총액 중앙을 로그 공간에서 결합 | 구성 합계와 별도인 경험적 참고 총액 |

### 2.3 v3 결합 방식

v3의 결합은 단순 산술 평균이 아닙니다.

```text
n = 비교 가능한 국내 같은 부품 그룹의 사례 수
w = n / (n + 2)
v3 중앙 = exp(w × ln(국내 총액 중앙) + (1-w) × ln(v2 총액))
n = 0이면 v3 중앙 = v2 총액
v3 범위 = [중앙 / exp(q), 중앙 × exp(q)]
기존 로그의 exp(q) ≈ 1.359
```

### 2.4 고정 입력

- 코드 기준일: 2026-10-08
- 환율: USD 1,340.00, EUR 1,501.07, GBP 1,770.94, INR 13.85
- CPI 기준 120.43, 평일 출장비 28,000원 등
- 이 환율·물가·출장비의 원출처는 재검증하지 않았으므로 현재 공식 값으로 표시하지 않음

### 2.5 보정 계수

- v1의 국내/해외 부품가 비율 중앙(기존 로그): 미국 0.308, 유럽 0.95
    - 개별 부품번호의 국내 관측 8건으로 만든 그룹 보정
    - 한국 공식 수리 부품 공급가 목록이 아님
- v2 기술료 중앙

## 5. 실행 입력·출력과 누락 파일

### 5.1 단계별 입출력

- README의 실행 순서: normalize → model → model_v2 → model_v3
- 실제 코드의 파일명은 README의 한국어 결과 이름과 다름

| 단계 | 실제 입력/의존 | 코드의 출력 |
| --- | --- | --- |
| normalize | `overseas_v1.csv`, 국내 LG 후기 CSV, 국내 삼성 후기 CSV | `out_overseas_normalized.csv`, `out_domestic_normalized.csv` |
| model | 위 정규화 2개 CSV, 코드 내부 KR_PART 관측값 | `out_estimate_table.csv`, `out_validation.csv` |
| model_v2 | model의 자료·함수, `out_validation.csv` | 비교 표를 콘솔에 출력, 별도 CSV 저장 없음 |
| model_v3 | model/model_v2와 `out_validation.csv` | `out_validation_v3.csv`, `out_model_compare.csv`, `out_estimate_table_v3.csv` |

### 5.2 입력 경로와 누락 파일

- 검토 당시 코드: 작성 당시 실행 환경의 절대 경로로 중간 CSV 폴더(`norm/`)와 `LG_AS_수리비_후기_사례.csv`, `삼성_AS_수리비_후기_사례.csv`를 직접 읽음
- 이후 변경: 경로를 환경변수 `COST_DATA_DIR`(지정하지 않으면 스크립트가 있는 폴더) 기준으로 변경, 계산 로직은 그대로
- 확인한 패키지 폴더에 없는 것: 국내 후기 원본, 정규화/검증 중간 CSV
    - 관련 Drive 검색에서도 원본을 확보하지 못함
    - 개발자의 다른 저장소까지 없다고 단정할 수는 없음

### 5.3 실행 환경

- 필요 라이브러리: pandas, numpy
- 패키지의 별도 의존성 고정 파일: 폴더 목록에서 확인되지 않음
- model을 import하면 CSV를 바로 읽으므로, 서버에서 `predict3`만 가져와 즉시 쓰는 방식도 입력 경로가 없으면 실패

### 5.4 현재 가능한 범위

- 가능: 이미 생성된 최종 표·로그·코드를 읽어 구조를 이해하고 고정 스냅샷 활용
- 원자료부터 재계산하려면 필요한 것
    - 국내 원본 확보
    - 경로 설정화
    - 라이브러리 버전 고정
    - 실제 출력과 배포 파일명의 대응

### 6.2 후속 검수가 필요한 부분

- `normalize_domestic`은 '견적만'을 표시하지만 유상 실결제 판단에서 그 플래그를 직접 제외하지 않음
    - 원본 확보 후 견적만인 사례의 학습 유입 확인 필요
- 부품비가 100원 미만이면 결측으로 바꾸고 일부 계산에 truthiness를 사용하므로 확인된 0원과 미기재가 섞일 수 있음
    - 무상 처리 전 정가와 실제 지불액을 따로 보존 필요
- 과거 출장비 미기재 사례를 추정값으로 보정하며, 여러 부품을 바꾼 후기도 단일 그룹으로 매핑될 수 있음
    - 당시 요금 가정·복합 수리 여부 명시 필요
- v3 보정 POOL은 고객과실 등을 제외하지만 기존 검증 목록에는 고객과실 W11 사례가 남아 있음
    - 학습 모집단과 평가 모집단의 조건 분리 검토 필요
- 최종 표에는 구성별 범위가 없지만 v1/v2 코드·로그에는 추정 범위가 있음
    - 입력·산출물을 확보해 검증하기 전 로그 범위를 현재 앱에 그대로 채우지 않음
- REFERENCE/독립 VALIDATION 분리와 중복 후기 제거 필요
    - 기존 LOO 기록만으로 독립 검증이 완료된 것으로 평가하지 않음
